## ADR-001: Dual-transport, protocol-first LightDM integration

- **Status**: Accepted (2026-08-12, commit `cdab0e8`)
- **Context**: LightDM 1.31+ removed the greeter D-Bus API (Seat.Authenticate/Respond/StartSession + ShowPrompt/ShowMessage/AuthenticationComplete signals); calls now fail with `UnknownMethod` on LightDM 1.32. Greeters must use the pipe-FD binary protocol instead.
- **Decision**: Implement the full pipe protocol (pkg/dbus/protocol.go) as the primary channel. Keep the legacy D-Bus method calls and signal listener as fallback for LightDM <= 1.30 and for seat/session property access (those properties still exist in 1.32).
- **Consequences**: Every auth method checks `proto.connected()` first. `Connect()` succeeds if either channel is live. Session discovery still prefers the D-Bus `Seat.Sessions` property, falling back to `.desktop` file scanning incl. NixOS paths.

## ADR-002: Scoped wallpaper affine transform (input integrity)

- **Status**: Accepted (2026-08-09, commit `5cf6ef0`)
- **Context**: The cover-fit transform in `drawWallpaper` was applied with `op.Affine(...).Add()`, which does not push the current transform. The leaked scale/offset corrupted every subsequent op of the frame — Gio's input router folds TypeTransform ops into hit-area transforms, breaking all pointer/keyboard input (no mouse, nothing selectable).
- **Decision**: Use `Push`/`Pop` to scope the transform to the wallpaper ops only.
- **Consequences**: Greeter input works; the fix was verified against the compiled Gio v0.10.1 sources (`op/op.go`, `io/input/router.go`, `io/input/pointer.go`).

## ADR-003: Headless build tags for CI without graphics deps

- **Status**: Accepted (2026-07-24)
- **Context**: Gio needs cgo + X11/Wayland/Vulkan dev libraries, making unit testing in CI and on minimal hosts impossible.
- **Decision**: `//go:build headless` / `!headless` split: the GUI (`window.go`, `layout.go`) compiles only without the tag; `headless.go` provides a stdin/stdout TUI with the identical `Window`/`UIActionHandler` API. The Nix package gets a `buildHeadless` flag that drops graphics build inputs and sets the tag.
- **Consequences**: `go test -tags headless ./...` runs everywhere; both build surfaces must stay API-parallel (headless tests catch drift).

## ADR-004: NixOS module + dual-output package (xgreeters)

- **Status**: Accepted (2026-07-24)
- **Context**: LightDM finds greeters via `.desktop` files in the greeters directory; the flake must integrate with NixOS lightdm without user fiddling.
- **Decision**: Package outputs `out` + `xgreeters` (the `.desktop` lives in both). NixOS module sets `lightdm.greeter.name/package` to the xgreeters output and forces `greeters.gtk.enable = false`. Stylix-aware options (`wallpaper`, `themeName`, `darkTheme`) inherit from `config.stylix` / `config.gtk`.
- **Consequences**: `services.xserver.displayManager.lightdm.greeters.ganapati.enable = true` is the whole integration surface.

## ADR-005: QEMU VM as the primary integration test bed

- **Status**: Accepted (2026-08-09)
- **Context**: Live-system deployment of the greeter is risky (login screen failures lock the user out). The project needs a safe integration environment.
- **Decision**: `nixosConfigurations.vm` — NixOS VM with LightDM + Ganapati, modesetting driver, Spice display (port 5900), serial console log, `testuser`/`testpassword`. Built via `just vm-build`, run via `just vm-run`. **The VM must run perfectly before any live deployment.**
- **Consequences**: Greeter changes get exercised in the VM first; the repo carries `nixos-greeter-test.qcow2` as the persistent VM disk.

## ADR-006: Optimistic password prompt

- **Status**: Accepted (2026-08-09)
- **Context**: The D-Bus/protocol round-trip before the password prompt adds perceived latency.
- **Decision**: `startAuth` switches the UI to the password field immediately; server prompts arrive asynchronously. Failures surface via `SetStatus`.
- **Consequences**: Snappier UX; a failed Authenticate shows an error status instead of blocking the UI.

## ADR-007: Functional-options style configuration

- **Status**: Accepted (2026-07-24)
- **Context**: The greeter needs defaults + overridable settings from `/etc/lightdm/lightdm-greeter-ganapati.conf`.
- **Decision**: `DefaultConfig()` constructor + INI loader; missing files yield defaults, never errors.
- **Consequences**: Standalone dev mode works with no config present.
